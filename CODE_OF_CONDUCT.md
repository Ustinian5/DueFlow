# Code of Conduct

DueFlow is a local-first desktop assistant project. The project works best when discussions stay practical, respectful and focused on improving the software.

## Expected Behavior

- Be respectful of other contributors, users and maintainers.
- Keep feedback specific, actionable and grounded in the project goals.
- Assume local privacy and user control are core product requirements.
- Disclose conflicts of interest when they affect a design or dependency recommendation.
- Help keep issues and pull requests reproducible with clear steps, logs and environment details.

## Unacceptable Behavior

- Harassment, threats, insults or discriminatory language.
- Publishing another person's private information without explicit permission.
- Repeatedly derailing technical discussions after maintainers have asked to refocus.
- Submitting intentionally harmful code, misleading test results or hidden network behavior.
- Pressuring maintainers to handle private support, security or legal issues in public threads.

## Scope

This code of conduct applies to project spaces including the repository, issues, pull requests, discussions, release channels and community chat spaces controlled by the project.

## Reporting

Report conduct concerns to the maintainers through a private channel when available. For security-sensitive issues, follow [SECURITY.md](SECURITY.md) instead of opening a public issue.

Include:

- a short description of the incident;
- links, screenshots or message references when available;
- whether immediate moderation is needed.

Do not include private API keys, private task data, raw screenshots with sensitive information, or local database files in a report.

## Enforcement

Maintainers may edit or remove comments, close issues, restrict participation, or block accounts when behavior harms the project or its contributors. Enforcement decisions should be proportional, documented where appropriate, and focused on restoring a productive project environment.
