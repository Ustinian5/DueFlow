# OpenPets 参考边界

本文记录 DueFlow 对 `reference/openpets` 的参考边界。OpenPets 只作为架构样板，不作为 DueFlow 的运行依赖，不复制其源码、素材或插件包。

## 明确不采用

- 不把 DueFlow 从 Tauri 改为 Electron。
- 不引入 OpenPets 的包、插件 SDK、资源文件、图片、音频或构建链。
- 不复用 OpenPets 的具体实现代码。
- 不复用 OpenPets 的交互细节或素材表现。

## 可参考原则

DueFlow 只吸收以下工程模式：

- 事件驱动：用事件连接桌宠输入、日程更新、气泡反馈和系统通知。
- 状态派生：从任务、风险、提醒和用户操作中派生桌宠状态。
- 动作注册：把左键互动、拖拽接收、隐藏、打开日程表、打开设置等动作声明化。
- 隔离边界：本地技能和桌宠形象使用 manifest 校验，不执行未知第三方代码。
- 窗口分层：桌宠、轻量日程表、控制中心分别承担不同职责。
- 失败隔离：文件解析、OCR、模型调用或桌宠动作失败时，只影响当前操作，并通过桌宠反馈原因。

## DueFlow 当前产品边界

当前产品要求以 [product_requirements.md](product_requirements.md) 为准：

```text
桌宠负责交互入口
日程表负责轻量展示
控制中心负责必要设置和少量修正
拖入内容后自动生成日程，不设置人工确认步骤
Windows 日程表采用侧边抽屉
macOS 日程表采用桌面组件
```
